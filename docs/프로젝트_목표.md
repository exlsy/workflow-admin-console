## 4.4 Babel 설치

```bash
npm install -D @babel/core@7 @babel/preset-env@7 @babel/preset-react@7 babel-loader@8
npm install -D @babel/plugin-proposal-class-properties@7
```

> ⚠️ **Babel은 반드시 7.x로 고정합니다.** 버전을 생략하면 최근 정식 출시된 Babel 8이 설치되어 `babel-loader@8`(Babel 8 미지원)과 `ERESOLVE` 충돌이 납니다. 또한 Babel 8에서는 `@babel/plugin-proposal-class-properties`가 제거되었습니다. 이 코스는 구형 스택(Webpack 4 + babel-loader 8)을 유지하므로 Babel 7이 정답입니다. (zsh에서 `@^7`은 glob 오류가 나므로 `@7`을 쓰거나 따옴표로 감싸세요.)

> `@babel/plugin-proposal-class-properties`는 class component에서 화살표 함수 메서드(`handleClick = () => {...}`)를 쓰기 위해 필요합니다. 7.1의 class 예제처럼 `this` 바인딩 없이 메서드를 정의하려면 이 플러그인이 있어야 합니다.

`.babelrc`

```json
{
  "presets": [
    [
      "@babel/preset-env",
      {
        "targets": {
          "browsers": [">0.25%", "not dead"]
        }
      }
    ],
    "@babel/preset-react"
  ],
  "plugins": ["@babel/plugin-proposal-class-properties"]
}
```

## 4.6.1 antd 설치

antd는 런타임 의존성이며 Day 4부터 사용합니다. 스타일시트를 별도로 import해야 화면이 정상 렌더링됩니다.

```bash
npm install antd@4 @ant-design/icons@4
```

> ⚠️ **antd는 v4로 고정합니다.** 버전을 생략하면 v5가 설치되는데, v5는 전역 CSS 파일(`antd/dist/antd.css`)이 없고(CSS-in-JS) `Modal`의 `visible` prop이 `open`으로 바뀌는 등 React 16/이 코스 예제와 어긋납니다. 아이콘은 v4에서 별도 패키지(`@ant-design/icons`)입니다.

CSS 로딩은 진입점(`src/index.jsx`)에서 한 번 import합니다(4.10 참고).

```jsx
import 'antd/dist/antd.css';
```

> antd v3와 v4 모두 CSS 경로는 `antd/dist/antd.css`로 동일하지만, Form API가 다르므로(7.5 참고) 설치된 버전을 먼저 확인하세요. 번들 크기를 줄이는 `babel-plugin-import`(온디맨드 로딩)는 이 코스 범위 밖이며, 전체 CSS를 import하는 방식으로 진행합니다.

## 4.7 Webpack 설정

`webpack.config.js`

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');
const { CleanWebpackPlugin } = require('clean-webpack-plugin');

// webpack-dev-server 3 + HMR은 [contenthash]를 지원하지 않으므로
// 개발 모드는 해시 없는 bundle.js, production만 contenthash를 사용한다.
const isProd = process.env.NODE_ENV === 'production';

module.exports = {
  mode: isProd ? 'production' : 'development',

  entry: './src/index.jsx',

  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: isProd ? 'bundle.[contenthash].js' : 'bundle.js',
    publicPath: '/',
  },

  resolve: {
    extensions: ['.js', '.jsx'],
    alias: {
      '@': path.resolve(__dirname, 'src'),
    },
  },

  module: {
    rules: [
      {
        test: /\.(js|jsx)$/,
        exclude: /node_modules/,
        use: {
          loader: 'babel-loader',
        },
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader'],
      },
      {
        test: /\.(png|jpg|jpeg|gif|svg)$/,
        use: [
          {
            loader: 'url-loader',
            options: {
              limit: 8192,
              name: 'assets/[name].[hash].[ext]',
            },
          },
        ],
      },
    ],
  },

  plugins: [
    new CleanWebpackPlugin(),
    new HtmlWebpackPlugin({
      template: './public/index.html',
    }),
  ],

  devServer: {
    historyApiFallback: true,
    port: 3000,
    open: true,
    hot: true,
    proxy: {
      '/api': {
        target: 'http://localhost:4000',
        changeOrigin: true,
        pathRewrite: { '^/api': '' },
      },
    },
  },

  devtool: 'source-map',
};
```

> **`pathRewrite`가 중요합니다.** axios는 `baseURL: '/api'`로 요청하지만(6장 참고) json-server는 `/requests`, `/users`를 제공합니다. `pathRewrite`가 없으면 요청이 `http://localhost:4000/api/requests`로 나가 **404**가 됩니다. `^/api`를 빈 문자열로 치환해야 `http://localhost:4000/requests`로 올바르게 전달됩니다.

> **`hot: true`와 React 16**: 이 설정만으로는 컴포넌트 state가 유지되는 진짜 HMR이 아니라 파일 변경 시 페이지 전체가 리로드되는 수준입니다. state를 유지하는 HMR은 `react-hot-loader` 설정이 필요하나 이 코스 범위 밖입니다.

## 4.8 package.json scripts

Node 20에서는 `--openssl-legacy-provider`가 필요하고, Windows에서 환경변수를 안전하게 지정하려면 `cross-env`가 필요합니다. 먼저 `cross-env`를 설치합니다.

```bash
npm install -D cross-env
```

처음부터 아래와 같이 통일해서 작성합니다.

```json
{
  "scripts": {
    "start": "cross-env NODE_OPTIONS=--openssl-legacy-provider webpack-dev-server --mode development",
    "build": "cross-env NODE_OPTIONS=--openssl-legacy-provider NODE_ENV=production webpack --mode production",
    "mock": "json-server --watch db.json --port 4000"
  }
}
```

> `cross-env`는 Windows/macOS/Linux에서 환경변수 지정 방식 차이를 흡수합니다. `NODE_OPTIONS=--openssl-legacy-provider`가 없으면 Node 17+ 환경에서 Webpack 4가 OpenSSL 오류로 실행되지 않습니다.

> **`mock` 스크립트는 별도 터미널에서 실행합니다.** `npm run mock`으로 json-server(:4000)를 먼저 띄운 뒤, 다른 터미널에서 `npm start`(:3000)를 실행해야 프록시가 정상 동작합니다.

## 5.1 로그인 mock 처리

> json-server는 `POST /login` 같은 인증 엔드포인트를 기본 제공하지 않습니다. 존재하지 않는 리소스로 POST하면 새 레코드가 생길 뿐 인증이 되지 않습니다.

이 코스에서는 학습 목적상 가장 단순한 방식을 사용합니다.

- `users` 목록을 `GET /api/users`로 조회한 뒤, 프런트에서 입력한 `username`과 비교하여 로그인 판정
- 로그인 성공 시 사용자 정보를 Redux `auth` 상태에 저장

> 실무에서는 서버가 토큰을 발급하고 `Authorization` 헤더로 인증하지만, mock 단계에서는 위 방식으로 흐름만 익힙니다. 필요 시 `json-server-auth`로 확장할 수 있으나 이 코스 범위 밖입니다.

## 5.2 인증 지속 (새로고침 유지)

Redux 상태는 새로고침 시 초기화되므로, 로그인 정보를 그대로 두면 새로고침할 때마다 `PrivateRoute`가 `/login`으로 되돌립니다. 이를 막기 위해 로그인 정보를 `localStorage`에 저장하고 앱 시작 시 복원합니다.

- 로그인 성공: 사용자 정보를 `localStorage`에 저장
- 앱 시작(`configureStore` 또는 `auth` reducer 초기 state): `localStorage`에서 복원
- 로그아웃: `localStorage`에서 제거

> `PrivateRoute`는 이 복원된 인증 상태를 기준으로 접근을 허용/차단합니다(8장 참고).

## 5.3 상태 변경과 처리 이력(history) 갱신

승인/반려/담당자 변경은 요청 레코드를 부분 수정하는 작업이므로 `PATCH /api/requests/:id`를 사용합니다.

- 상태 필드 변경: `PATCH`로 `status`, `assignee` 등만 전송
- `history` 배열 추가: json-server는 배열에 자동 append를 해주지 않으므로, **기존 `history`를 읽어 새 항목을 더한 전체 배열을 `PATCH`로 다시 보냅니다**

```js
// 예: 승인 처리 시 history에 한 줄 추가
const next = [...request.history, { message: '승인되었습니다.', createdAt: now }];
await requestApi.patchRequest(id, { status: 'APPROVED', history: next });
```

> 서버가 append를 대신 해주지 않으므로, 항상 최신 `history`를 기준으로 새 배열을 만들어 보내야 이력이 유실되지 않습니다(Day 13에서 사용).

# 7. 구형 React 프로젝트에서 반드시 알아야 할 항목

## 7.1 Class Component 읽기

React 16 프로젝트에는 class component가 남아 있을 수 있습니다.

```jsx
class RequestList extends React.Component {
  componentDidMount() {
    this.props.fetchRequests();
  }

  render() {
    return <Table dataSource={this.props.requests} />;
  }
}
```

새로 작성은 함수형 컴포넌트로 하더라도, 기존 코드는 class component를 읽을 수 있어야 합니다.

---

## 7.2 생명주기 메서드

Hooks의 `useEffect`와 연결해서 이해하면 좋습니다.

```txt
componentDidMount      → 최초 마운트 후 실행
componentDidUpdate     → props/state 변경 후 실행
componentWillUnmount   → 제거 직전 실행
shouldComponentUpdate  → 리렌더 여부 제어
```

---

## 7.3 connect 패턴

구형 Redux 프로젝트에서는 hooks보다 connect 패턴이 더 많습니다.

```jsx
function RequestList({ requests, fetchRequests }) {
  React.useEffect(() => {
    fetchRequests();
  }, [fetchRequests]);

  return <Table dataSource={requests} />;
}

const mapStateToProps = state => ({
  requests: state.requests.items,
});

const mapDispatchToProps = {
  fetchRequests,
};

export default connect(
  mapStateToProps,
  mapDispatchToProps
)(RequestList);
```

---

## 7.4 Redux Toolkit보다 Classic Redux 먼저

최신 프로젝트라면 Redux Toolkit을 권장하지만, 기존 React 16 프로젝트라면 다음 구조를 먼저 익히는 것이 좋습니다.

```txt
actions.js
reducer.js
selectors.js
constants.js
```

실무 코드가 이 형태일 가능성이 높기 때문입니다.

---

## 7.5 antd Form 버전 확인

antd v3:

```txt
Form.create()
getFieldDecorator
```

antd v4:

```txt
Form.useForm()
name prop
onFinish
```

기존 프로젝트가 antd v3라면 v4 문서만 보고 학습하면 오히려 혼란스러울 수 있습니다.
